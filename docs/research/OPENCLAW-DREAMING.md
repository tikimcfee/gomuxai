# What OpenClaw's Dreaming Actually Does

Checked against OpenClaw's [Dreaming docs](https://docs.openclaw.ai/concepts/dreaming), [Memory configuration reference](https://docs.openclaw.ai/reference/memory-config), and `memory-core` source in [`openclaw/openclaw`](https://github.com/openclaw/openclaw/tree/main/extensions/memory-core/src).

## 1. Phases, I/O, schedule, and handoffs

Dreaming in `memory-core` is **enabled by default** (`dreaming.enabled: true`) as **one** managed cron sweep (`0 3 * * *`, key `memory-core:memory-dreaming-promotion`; legacy separate Light/REM cron jobs are retired by `openclaw doctor --fix`). On each `cron` or `heartbeat` trigger ([`dreaming.ts`](https://github.com/openclaw/openclaw/blob/main/extensions/memory-core/src/dreaming.ts)), each workspace runs three sequential phases under one timestamp, then one sweep-level diary pass:

1. **Light** ([`dreaming-phases.ts`](https://github.com/openclaw/openclaw/blob/main/extensions/memory-core/src/dreaming-phases.ts)) — **deterministic, no LLM.** Chunks changed `memory/YYYY-MM-DD.md` notes (14-day recurrence horizon, stripping managed `## Light/REM Sleep` blocks) and interactive session transcripts (saved to `memory/.dreams/session-corpus/`, excluding cron/heartbeat/subagent/forgotten sessions and runtime-recalled snippets) into the SQLite recall store. Filters to `lookbackDays: 2`, dedupes at Jaccard `0.9`, prioritizes snippets uncovered by the last four diary entries (`limit: 100`), writes optional `## Light Sleep` reports (`memory/dreaming/light/YYYY-MM-DD.md` by default, or inline in daily notes), and records `lightHits` plus staged keys in SQLite. Never touches `MEMORY.md`.
2. **REM** ([`dreaming-phases.ts`](https://github.com/openclaw/openclaw/blob/main/extensions/memory-core/src/dreaming-phases.ts)) — **deterministic, no LLM.** Reads the `7`-day window, **preferring keys staged by Light** (`readLightStagedKeys`, falling back to the full window if empty). Tallies normalized `conceptTags` (`minPatternStrength: 0.75`, `limit: 10`) and ranks unpromoted "candidate truths" (`0.45*avgScore + 0.25*recallStrength + 0.20*consolidation + 0.10*conceptual >= 0.45`, Jaccard `0.88`, top 3). Writes `## REM Sleep` reports and records `remHits` in SQLite to boost Deep ranking. Never touches `MEMORY.md`.
3. **Deep** ([`short-term-promotion.ts`](https://github.com/openclaw/openclaw/blob/main/extensions/memory-core/src/short-term-promotion.ts), [`short-term-promotion-apply.ts`](https://github.com/openclaw/openclaw/blob/main/extensions/memory-core/src/short-term-promotion-apply.ts), [`dreaming-consolidation.ts`](https://github.com/openclaw/openclaw/blob/main/extensions/memory-core/src/dreaming-consolidation.ts)) — **ranker + tool-free LLM.** Repairs dangling recall rows, ranks candidates with Light/REM boosts, rehydrates live source files, drops `untrusted`/`system` origins, and asks an isolated completion for JSON operations (`added`, `merged`, `superseded`) on `MEMORY.md`—falling back to append-only `## Promoted From Short-Term Memory` sections on failure. Atomically writes `MEMORY.md`, stamps `promotedAt` in SQLite, and updates `## Deep Sleep` and `## Memory Consolidation History` in `DREAMS.md`.
4. **Dream Diary** ([`dreaming-narrative.ts`](https://github.com/openclaw/openclaw/blob/main/extensions/memory-core/src/dreaming-narrative.ts)) — **tool-free LLM.** After Deep finishes, the sweep merges in-memory `NarrativePhaseData` from Light, REM, and Deep into one completion appended to `DREAMS.md`, even when nothing promoted.

## 2. Speculative thinking, prompting, and review

**No stage proposes ideas, refactors, or counterfactual plans.** Light and REM do zero inference; Deep's `CONSOLIDATION_SYSTEM_PROMPT` forbids prose (`"do not return memory text or replacement prose"`), letting the model only select `priorEntries` while host code formats bullets.

The sole associative prompt is `NARRATIVE_SYSTEM_PROMPT` ([`dreaming-narrative.ts`](https://github.com/openclaw/openclaw/blob/main/extensions/memory-core/src/dreaming-narrative.ts)), requesting an 80–180 word first-person diary entry (*"a poet who happens to be a programmer"*, *"unexpected connections and small epiphanies"*, haikus or sketches, banning `"AI"`, `"agent"`, and `"dreaming"`). It is purely literary retrospection.

- **Prompting parameters:** Although [`src/memory-host-sdk/dreaming.ts`](https://github.com/openclaw/openclaw/blob/main/src/memory-host-sdk/dreaming.ts) parses per-phase `execution` presets (`speed`, `thinking: "low"|"medium"|"high"`, `budget`, `temperature`, `maxOutputTokens`), `memory-core` **never passes `temperature`, `thinking`, or `maxOutputTokens`** to `subagent.complete` ([`server-plugin-subagent-runtime.ts`](https://github.com/openclaw/openclaw/blob/main/src/gateway/server-plugin-subagent-runtime.ts) forwards only `agentId`, `model`, `extraSystemPrompt`, `message`, `timeoutMs`). Completions use the workspace agent's default model unless `dreaming.model` is allowlisted (`subagent.allowModelOverride: true`), retrying once with the default model if unavailable.
- **Destination and review:** Entries land in `DREAMS.md` (Gateway **Dreams** UI) for passive human reading, with no action queue; contamination and path filters block `DREAMS.md` and phase reports from promoting into `MEMORY.md`. (Bundled [`memory-wiki`](https://docs.openclaw.ai/plugins/memory-wiki) tracks `openQuestions` and `contradictions`, still strictly for knowledge curation.)

## 3. Scoring, thresholds, and checking our summary

Deep ranking sums relevance (`0.30`), log-frequency (`0.24`), interactive query diversity (`0.15`), 14-day recency (`0.15`), multi-day consolidation (`0.10`), and concept-tag density (`0.06`), plus recency-decayed phase boosts (`<= 0.06` Light, `<= 0.09` REM). Promotion (`limit: 10`, `maxAgeDays: 30`) requires **all three** gates ([`src/memory-host-sdk/dreaming.ts`](https://github.com/openclaw/openclaw/blob/main/src/memory-host-sdk/dreaming.ts)): `minScore = 0.75` (calibrated for 3-day/3-query facts; some secondary posts cite `0.8`), `minRecallCount = 3` (total signals), and `minUniqueQueries = 3` (interactive `userQueryHashes` only).

Checking `docs/DREAMING.md`'s one-line summary:

- **Light and REM only stage — Right.** Neither writes `MEMORY.md`; they write SQLite recall/phase signals and optional report blocks.
- **Deep is the only writer behind score thresholds — Right.** Only `applyShortTermPromotions` writes `MEMORY.md`, behind all three gates, live rehydration, and `untrusted`/`system` taint exclusion.
- **Rejected if it drops >25% of prior entries — Right (with fallback).** `phases.deep.maxPriorEntryLossFraction = 0.25` blocks over-pruning in consolidation and budget compaction—but a rejected LLM plan **falls back to append-only promotion**.
- **...or loses a source — Partly wrong (narrower than `gomuxai`).** Host code builds every *new* bullet with `Source: path#Lx-Ly`, enforces project-group isolation, requires normalized-fact equality on `merged`, and checks `<!-- openclaw-memory-lineage:... -->` on `superseded`. It does **not** scan prior `MEMORY.md` entries for lost `Source:` tags; unrelated lines survive because host code splices `priorEntries` out rather than accepting LLM-written prose.
- **Prior file is saved — Right, in SQLite (consolidation only).** [`storeMemoryPreimage`](https://github.com/openclaw/openclaw/blob/main/extensions/memory-core/src/dreaming-consolidation-artifacts.ts) stores the latest 8 `MEMORY.md` preimages in SQLite plugin state before consolidated rewrites, not on the append-only fallback path.
- **`DREAMS.md` diary — Right.** Holds `# Dream Diary`, `## Deep Sleep`, and `## Memory Consolidation History`.

## 4. "Dream freely" proposal modes elsewhere

Neither [Generative Agents](https://arxiv.org/abs/2304.03442) nor [Letta / Sleep-time Compute](https://arxiv.org/abs/2504.13171) ([docs](https://docs.letta.com/configuration/memory)) pitches ideas to a person; both write back into agent memory. Systems emitting **human-reviewed proposals** instead:

- **[Google AI Co-Scientist](https://arxiv.org/abs/2502.18864):** Asynchronous Generation, Reflection, Evolution, and Elo-tournament agents output ranked **research proposals** (hypothesis, novelty critique, validation plan) for a human scientist—never self-executed.
- **[Mueller's `DAYDREAMER`](https://github.com/eriktmueller/daydreamer) and [LLM Day-Dreaming Loops](https://gwern.net/ai-daydreaming):** Run counterfactual "what-if" episodes on blocked goals or pair distant notes/repos through a high-variance generator + strict critic filter to surface non-obvious syntheses.
- **[Sakana's The AI Scientist](https://arxiv.org/abs/2408.06292) and [`trace2rules`](https://github.com/rkkautsar/trace2rules):** Score speculative directions for novelty/feasibility or stage `audit --proposal` diffs; AI Scientist's reward-hacking under self-execution shows why bold proposals need a human gate.

## What this means for a vision tier

1. **Air-gap pitches from `memory/`, `friction`, and `act`.** Like OpenClaw's non-promotable `DREAMS.md`, store vision pitches in a dedicated table/inbox (`pitched | parked | promoted | dismissed`) surfaced in `agent fleet` and the manager UI—never in `memory/` or `act`.
2. **Seed synthesis from cross-project pain, not poetic mood.** Run sparsely after `dream run --global` over cross-repo `evidence` clusters, multi-project `start_here.md` workarounds, repeated `large` act-gate hits, and paired `ARCHITECTURE.md` digests.
3. **Pair a divergent generator with a cross-family critic, allowing zero output.** Wire high reasoning/temperature on a `--task design` generator, then let another model family (`--task review`, Co-Scientist style) kill ideas already in git/docs, lacking cross-repo leverage, or matching `dismissed` pitches—emitting 0–2 pitches per run.
4. **Require an RFC contract with a bounded first spike.** Every pitch must cite verified `dream_items` (`review::unknown_citations`), explain why a local `act` patch is insufficient, list affected repos/interfaces, and give a one-command read-only or worktree spike for a person to approve.
