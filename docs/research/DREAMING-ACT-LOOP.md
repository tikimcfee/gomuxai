# Closing the Loop: When a Dream Finds Something to Fix

`docs/DREAMING.md` splits dreaming into **Consolidate** (read-only memory curation and friction triage) and **Act** (later: fixing accepted friction in a worktree), while `docs/research/DREAMING-SURVEY.md` surveys offline consolidation broadly. This note addresses the boundary between them: **how a "thing to fix" should live before and after a fix lands, without rotting memory.**

A durable memory states an invariant (*"X holds"*); a defect states a pending transition (*"X is broken until fixed"*). Storing a defect as a memory guarantees staleness the moment the fix lands, and worse, creates fan-out—a `start_here.md` tripwire, a project note, a global note—none of which close atomically with the commit.

## 1. Separating durable memory from work items

Systems that survive long horizons enforce a hard type boundary between **standing knowledge** and **open work**:

- **Actionable graphs vs. invariant prose.** [Beads](https://github.com/steveyegge/beads) was built specifically because coding agents stuffing discovered bugs and TODOs into `AGENTS.md` or `CLAUDE.md` caused context bloat and session-to-session confusion between standing rules and unfinished tasks. Beads moves actionable items into a SQLite/Git-backed issue graph (`bd create`, `discovered-from` provenance edges, `bd ready`, `bd close`) while keeping Markdown strictly for durable invariants.
- **Derivability and task boundaries.** [Claude Code Auto Memory](https://code.claude.com/docs/en/memory) separates transient session Tasks from `memory/` (`user`, `feedback`, `project`, `reference`), explicitly excluding TODOs and anything derivable from code or `git log`. This mirrors Zettelkasten's split between an actionable inbox (items meant to be discharged) and evergreen notes (claims meant to endure).
- **Closing from the change artifact.** Issue trackers ([GitHub closing keywords](https://docs.github.com/en/issues/tracking-your-work-with-issues/using-issues/linking-a-pull-request-to-an-issue), [Linear Git integration](https://linear.app/docs/github)) never rely on someone remembering to clean up prose later; commit trailers (`Fixes #123`) bind closure atomically to the commit landing on the default branch, recording bidirectional provenance between ticket and commit hash.

## 2. Time-aware facts and "derive, don't remember"

When knowledge changes over time, systems avoid stale state in two ways: tracking validity intervals or checking live truth on read.

- **Bitemporal and event-sourced memory.** [Zep / Graphiti](https://arxiv.org/abs/2501.13956) ([code](https://github.com/getzep/graphiti)) and bitemporal databases like [XTDB](https://docs.xtdb.com/about/time-in-xtdb) and [Datomic](https://docs.datomic.com/) separate *transaction time* (`created_at`, `expired_at`—when the store recorded or retired a belief) from *valid time* (`valid_at`, `invalid_at`—when the fact held in the world). Contradictions never overwrite in place; setting `invalid_at` keeps wakeup queries clean (`invalid_at IS NULL`) while preserving why earlier sessions acted as they did.
- **Just-in-time verification ("derive, don't remember").** [GitHub Copilot's agentic memory](https://github.blog/ai-and-ml/github-copilot/building-an-agentic-memory-system-for-github-copilot/) binds every stored repository memory to `path:line` code citations and verifies those spans against the live checkout *at session wakeup*, discarding or self-healing drifted memories alongside an inactivity TTL. [Claude Code](https://code.claude.com/docs/en/memory) similarly drops code-derivable facts and rewrites relative dates (*"recently"*, *"currently broken"*) that rot silently without a date or commit anchor.

## 3. Turning reflections into verified actions

Open-loop reflection emits advice without testing whether failures stop. Closed-loop agent systems gate retention on empirical outcomes:

- **Utility-weighted rules.** [ExpeL](https://arxiv.org/abs/2308.10144) scores extracted rules across rollouts via `ADD`, `EDIT`, `UPVOTE`, and `DOWNVOTE`, deleting rules whose weight hits zero. [ReasoningBank](https://arxiv.org/abs/2509.25140) distills contrastive strategies—including explicit failure pitfalls—and validates gains under test-time scaling. [Reflexion](https://arxiv.org/abs/2303.11366) and [Voyager](https://arxiv.org/abs/2305.16291) keep a verbal or skill fix only after an execution critic confirms the next trial passes.
- **Patch-and-benchmark loops.** [SWE-agent](https://arxiv.org/abs/2405.15793), [Self-Improving Coding Agent (SICA)](https://arxiv.org/abs/2504.15228), and [Darwin Gödel Machine](https://arxiv.org/abs/2505.22954) turn trajectory failures into isolated branch patches gated by test suites rather than self-reported completion. Crucially, [`trace2rules`](https://github.com/rkkautsar/trace2rules) shows that prose rules in `AGENTS.md` are still violated in 30–100% of sessions—demonstrating that recurring prose tripwires should graduate into deterministic CLI or hook guards.

## 4. Retiring memory when the fix lands

Four patterns govern how stale notes leave active context:

- **Supersession chains.** [Michael Nygard's Architecture Decision Records](https://cognitect.com/blog/2011/11/15/documenting-architecture-decisions) and $\text{Mem0}^g$ ([arXiv:2504.19413](https://arxiv.org/abs/2504.19413)) never delete reversed decisions; they mark old records `Superseded by ...` so current truth leads while historical *why* remains auditable.
- **Tombstones over raw deletion.** Deleting a note outright fails twice in offline consolidators: old sessions can re-extract the deleted claim if re-read, and provenance guards treat missing citations as data loss. A tombstone (retired status on disk) keeps provenance countable while removing the note from active indexes.
- **Decay only as a backstop.** Smooth recency decay ([Generative Agents](https://arxiv.org/abs/2304.03442), [MemoryBank](https://arxiv.org/abs/2305.10250)) is ill-suited to bugfixes: a fixed workaround lingers to mislead waking agents, while a rare, still-true build invariant fades. Verified fixes should retire workarounds immediately; age caps belong only on unverified workarounds.
- **Hub-and-spoke backlinks.** Fan-out (*"ten notes about one change"*) disappears when workaround notes cite one canonical work-item ID instead of describing the defect independently: closing that single ID deterministically locates every note that cited it.

## Mapping onto `gomuxai`

`gomuxai` already has almost every primitive needed—`friction` (`rs/crates/agent-store/src/friction.rs`) with votes, `accept`, `resolve`, and cross-host `friction_links`; memory files with `[source: ...]` citations (`rs/crates/agent-dream/src/memory.rs`); normalized error signatures (`evidence.rs`); and citable commits and sessions. Three concrete rules connect them:

1. **Where "needs fixing" goes:** Always into `friction`, never as a standalone `memory/` file and never stranded as untracked prose at the bottom of `dreams.diary` (`brief.md`, `brief_global.md`). Memory mentions an unfixed problem *only* when waking agents need an active workaround (*"While X fails, do Y instead"* in `start_here.md` Tripwires or a `feedback` note). Every such workaround **must cite `friction:<uid>`** as its hub (`[source: friction:<uid>, claude:<id>, ...; added: YYYY-MM-DD]`).
2. **What closes it:** `agent friction resolve <id> --commit <hash>` (or a `Fixes: friction:<uid>` commit trailer), propagated across `friction_links`, followed by `evidence.rs` verifying that the normalized failure signature drops to zero on builds after `resolved_at`.
3. **What happens to memory that mentioned it:** Today `memory.rs` inadvertently traps obsolete workarounds: `check_fact_rewrite` refuses removing a fixed Tripwire from `start_here.md` if its citation leaves that file, `remove` refuses deleting a file unless an active note absorbs its citations, and `check` flags any unindexed `.md` file as `Finding::Unindexed`. Marking the workaround file `metadata.superseded_by: commit:<hash>` turns it into an on-disk tombstone: `start_here.md` drops the Tripwire line, `MEMORY.md` drops the index entry, `memory::guard` still sees every citation on disk, and waking agents read zero stale prose.

## Five recommendations for `gomuxai`

1. **Give dreams a cited `agent dream friction file` verb that auto-votes on matches, and forbid defect-only memories.** Add `project` and `sources` columns to `FRICTION_SCHEMA` in `rs/crates/agent-store/src/friction.rs` (migrated in `sqlite.rs`). Generalize `limitation` in `rs/crates/agent/src/cli/dream.rs` (and `DREAM_AGENT_COMMANDS` in `agent-service`) into `agent dream friction file "<summary>" --kind <kind> --source <ref>[,...] [--project <dir>]`: verify `--source` against the dream's items, run `similar_friction` on open/accepted entries, and record a de-duplicated `+1` `FrictionVote` on matches instead of dropping them as `limitation` does today. Update `brief.md` and `brief_global.md` so defects go to `friction` and any workaround memory must cite `friction:<uid>`.
2. **Bind `friction resolve` to a verified commit (`--commit <hash>` and git trailers) and re-gather closed friction cited by memory.** Add `resolved_commit` to `friction` (and `peer_resolved_commit` to `friction_links`), and add `--commit <hash>` to `FrictionResolveArgs` in `rs/crates/agent/src/cli/friction.rs`, checked via `commit_in_repo` (`git cat-file -e`). In `rs/crates/agent-dream/src/gather.rs`, scan `CommitIn` messages for `Fixes: friction:<uid>` / `Fixes #<id>` trailers, and surface newly closed `friction` entries in both project `gather` and `gather_global` whenever any file in the gathered `memory/` dirs cites `friction:<uid>` (even if closed before a dream reviewed it).
3. **Add `metadata.superseded_by` tombstones and directory-wide citation accounting in `rs/crates/agent-dream/src/memory.rs`.** Parse optional `metadata.superseded_by` (`commit:<hash>`, `wontfix:<uid>`, or `[[memory]]`, mirroring `RosterNote::supersedes` in `agent-store/src/roster.rs`) in `parse_frontmatter`. Let `check_fact_rewrite` in `put` drop citations from `start_here.md` (or rewritten notes) whenever those citations remain on disk in another file of `dir`, relying on `memory::guard`'s whole-directory `CitationLost` check—which keeps counting citations in superseded files while exempting them from `FilesGone`. Teach `memory::check` to skip `Finding::Unindexed` for superseded files, flag any superseded file still listed in `MEMORY.md` or `[[linked]]` from `start_here.md`, and verify `superseded_by` targets in `review::unknown_citations` (`review.rs`).
4. **Extend `agent dream memory check` (`rs/crates/agent-dream/src/stale.rs`) with `stale-friction` and `code:` span checks.** Pass a friction-status lookup into `stale::Repos` from `rs/crates/agent/src/cli/dream_memory.rs` so `stale::check` emits `Finding::StaleFriction` (naming `resolved_commit` and `resolution`) for every active memory citing a `resolved` or `wontfix` `friction:<uid>`. Allow optional `code:<path>:<start>-<end>@<blob>` refs in `parse_sources` (`memory.rs`) so `stale::check` flags `Finding::StaleCode` when cited lines change in `Repos`, catching code drift deterministically before spawning an LLM.
5. **Verify fix efficacy via cross-dream failure signatures in `evidence.rs` and close the loop in `dream_act.rs`.** Store normalized `(what, error)` signatures (`command_shape` + `normalize_error` in `rs/crates/agent-dream/src/evidence.rs`) on `friction` entries. In `rs/crates/agent/src/cli/dream_evidence.rs`, compare signature rates across builds after `resolved_at`: mark zero-rate fixes verified for workaround retirement, flag post-fix recurrences as regressions in the digest, and promote prose Tripwires that keep firing across two dreams into `friction` candidates for CLI/hook guards. When building the Act layer (`dream_act.rs`), run accepted items in a worktree (`--task bugfix`), gate on diff size, `agent run` checks, a separate `--task review` session, and a hook self-test canary before calling `agent friction resolve <id> --commit <hash>`.
